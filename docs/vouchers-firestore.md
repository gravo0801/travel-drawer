# DRAWER 카드 혜택 위젯 — 데이터 보관 및 Firestore 설정

## 1. 화면과 기록

- `/me`에 로그인한 후 `오버뷰`의 `카드 혜택` 위젯 또는 좌측/모바일의 `카드 혜택` 메뉴에서 관리합니다.
- 혜택마다 카드사, 카드명, 혜택명, 귀속 연도/기간, 제공 횟수, 만료일 및 메모를 기록합니다.
- 사용 기록은 `예약·적용`과 `사용 완료`로 구분합니다. 호텔 숙박을 예약했다고 해서 투숙 완료로 표시하지 않습니다.
- 예약·적용 항목은 실제 사용 이후 `이용 완료로 전환`할 수 있습니다.
- JSON 내보내기/가져오기 지원. 카드번호, CVV, 인증 토큰, 예약번호, 주민등록번호 등 민감정보는 기록하지 마세요.
- 혜택 만료일은 실제 카드 발급사 안내를 확인하여 직접 입력합니다. 모든 카드의 혜택 주기가 1월 1일 시작되는 것은 아닙니다.

## 2. 데이터 저장 방식

- 기본값: 로그인 사용자 UID별 **브라우저 로컬 저장소**(`drawer.vouchers.v1.<uid>`).
- 개인 사용 데이터는 이 공개 GitHub 저장소의 JSON 파일에 기록되지 않습니다.
- `클라우드로 저장` 버튼을 명시적으로 누른 뒤에만 **Firebase Cloud Firestore**를 연결합니다.
- 연결에 성공한 기기는 클라우드 데이터 변경을 구독합니다. 데이터 갱신은 Firestore가 허용하는 범위 내에서 실시간 반영됩니다.
- 권한 오류나 DB 미설정시 로컬에 저장하며 오류가 표시됩니다. 로컬/클라우드 충돌 시 `클라우드로 저장`을 누르면 덮어쓰기 확인이 나옵니다.
- 브라우저 로컬 저장소는 같은 기기의 해당 브라우저 프로필에만 남습니다. 브라우저 데이터 삭제 전 JSON 백업을 권장합니다.

## 3. Firestore 활성화 및 보안 규칙

1. DRAWER가 로그인에 사용하는 **같은 Firebase 프로젝트**의 Firebase Console에서 Cloud Firestore 데이터베이스가 활성화되어 있는지 확인합니다.
2. 프로젝트의 기존 Firestore 보안 규칙을 반드시 백업합니다.
3. 기존 다른 앱/컬렉션 규칙을 지우지 않고, 아래 **컬렉션 전용 match 블록**을 기존 `match /databases/{database}/documents` 범위 안에 추가합니다.
4. 규칙을 게시합니다. 필요한 경우 이미 배포된 규칙이 다른 광역 `allow read,write`를 허용하지 않는지도 확인합니다. Firestore 규칙은 **일치하는 어떤 규칙 하나라도 허용하면** 접근이 허용되므로 전체 규칙의 검토가 필요합니다.
5. DRAWER `/me`에서 `클라우드로 저장`을 누르고 성공 표시를 확인한 다음, 다른 기기에서 같은 Google 계정으로 들어가 동일 기록이 보이는지 확인합니다.

컬렉션 전용으로 추가할 규칙 **예시**:

```text
match /drawer_voucher_ledgers/{userId} {
  allow get, create, update, delete:
    if request.auth != null && request.auth.uid == userId;
  allow list: if false;
}
```

이 코드 조각만 단독으로 배포하지 마세요. 기존 rules_version 및 다른 컬렉션 규칙을 유지한 전체 규칙 문서에 **병합**해야 합니다.

## 4. 제한과 향후 기능

- ChatGPT 프로젝트 대화·메모리는 DRAWER에 자동 전송되지 않습니다. 기존 기록은 JSON 가져오기를 통해 초기 반영할 수 있습니다.
- Firestore 규칙 게시를 이 코드 배포만으로 자동화하지 않습니다. Firestore 사용 전에는 관리자가 데이터베이스와 보안 규칙을 확인해야 합니다.
- 앱을 열어 놓았을 때 만료일 D-day를 보여 줍니다. 이메일·푸시 알림 발송은 아직 구현하지 않았습니다.
- 복수 기기에서 같은 혜택을 **동시에** 수정하면 마지막 저장값이 이길 수 있습니다. 고빈도 다중 사용자 편집 용도가 아닙니다.
